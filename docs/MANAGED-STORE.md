# Управляемый магазин — текущее состояние

## Что работает
React/Vite оставлены без смены платформы. Express 5 + встроенная SQLite Node 24 — один сервер и один постоянный диск. Исходная праздничная витрина, отдельный PNG Деда Мороза, ТВ-презентация, поиск, фильтры, сравнение и демо-режим сохранены.

`/admin`: защищённый кабинет. Создание и редактирование товаров, до 8 фотографий, обложка, название, бренд, категория, цена, остаток, диагональ, состояние, описание и характеристики. Черновик / публикация / снятие с публикации / архив. Изменения видны на публичной витрине после обновления; кабинет также обновляет данные текущей вкладки. Для публикации нужна фотография. При нулевом остатке покупка недоступна.

Оформление реального товара создаёт запись заказа в SQLite. Цена берётся только из БД и проверяется против показанного покупателю итога, остаток резервируется атомарно. Повтор того же запроса не создаёт второй заказ. Магазин видит контакты, состав, суммы и время заказа в кабинете; может подтвердить, завершить или отменить заказ. Отмена возвращает остаток один раз. При изменении товара параллельным заказом старый редактор не может перезаписать остаток.

Онлайн-оплата, автоматические SMS/email, логистика, аккаунты покупателей, Ozon/WB не подключены. Заказ требует подтверждения продавца. Адрес магазина, правила доставки/гарантии и юридические реквизиты не выдуманы: владелец должен предоставить их перед публичными продажами. Пример 30–70% на ТВ подписан как не действующая акция. Демо-товары остаются отдельными, на сервер их заказать нельзя.

## Первый вход — безопасная настройка владельцем
В runtime-архиве с готовым `dist` повторная сборка не нужна: `npm ci --omit=dev --ignore-scripts`, затем настройка администратора и `npm start`. Команды сборки/тестов ниже относятся к полному исходному архиву.
Нужен Node **24.22+ версии 24.x**. В проекте:

```sh
npm ci --ignore-scripts
cp .env.example .env
npm run setup:admin
npm run build
npm start
```

`setup:admin` интерактивно запрашивает логин и скрытый пароль (14–256 символов), сохраняет только scrypt-хэш с солью в `DATA_DIR/admin-auth.json` с правами 0600. Пароля по умолчанию нет. Пароль не передавайте через чат, аргументы команд или исходники. Повтор команды сбрасывает вход и делает старые сессии недействительными; перезапуск приложения не нужен. Можно вместо файла передать `ADMIN_USERNAME` / `ADMIN_PASSWORD_HASH` через защищённое окружение сервера. Браузер получает только случайную HttpOnly SameSite=Strict cookie на 8 часов; при HTTPS она Secure.

В текущем BOX администратор намеренно **не настроен**, чтобы не придумывать и не пересылать владельцу пароль. Нужно выполнить только защищённую настройку выше. Runtime уже запущен и каталог пуст, без тестовых товаров.

Локальная разработка: `npm start` (API 5175) + `npm run dev` (витрина 5174, proxy `/api` и `/media`). Для единственного production-сервера задайте `SITE_ORIGIN` реальному адресу этого сервера и открывайте его порт, а не Vite preview. Изменение `.env` требует перезапуска. API принимает изменяющие запросы только с точного разрешённого Origin. `ADDITIONAL_ORIGINS` — явный необязательный список через запятую, обычно не нужен. Не включать `TRUST_PROXY=1`, если перед сервером нет доверенного прокси.

## Фото и защита
Загрузка только после входа. До 8 МБ, JPEG/PNG/WebP от 64 px, до 25 Мп, без анимации. Sharp проверяет реальный формат и полностью перекодирует в WebP, убирая метаданные; максимальная сторона результата 2400 px без увеличения. SVG/HTML, подмена MIME, повреждённые/чрезмерные файлы отклоняются. Имена файлов — случайные UUID, пути пользователя не принимаются. Публично доступны только `/media/<uuid>.webp`, не БД или настройки. Лимиты попыток входа, отправки заказов и загрузок действуют на IP в рамках процесса; внешняя защита от массового распределённого спама не заявляется. Публичный production без HTTPS запрещён при запуске. Данные покупателя не пишутся в логи.

## База, миграции и резервные копии
`DATA_DIR` по умолчанию: соседний с проектом `../technoimperiya-private/data`, каталог 0700. В нём `store.sqlite`, WAL/SHM, `uploads/`, опционально `admin-auth.json`. Всё это вне `public/` и `dist/`; ни один приватный файл не включается в архивы поставки. SQLite schema v1 создаётся автоматически и записывается в `migrations`. Для следующих версий нужны новые явные миграции: удалять БД или заменять её пустой запрещено.

Согласованная резервная копия, передайте НОВЫЙ каталог на защищённом диске:

```sh
npm run backup -- /secure/backups/shop-YYYY-MM-DD
```

Команда делает SQLite `VACUUM INTO` и копирует фотографии. Для полностью согласованной пары БД + фото на время копии приостановите администраторские загрузки/правки (либо остановите приложение): веб-заказы могут продолжать сохраняться после SQLite-снимка и в этот снимок не попадут. Хэш администратора сохраните отдельно в защищённом хранилище. Для восстановления остановите сервер, восстановите `store.sqlite` и `uploads`, уберите старые WAL/SHM только у остановленной базы, верните права владельцу процесса/0600 и запустите сервер. Не раздавайте резервные копии через веб-сервер.

## Размещение: конкретный оставшийся блокер
В существующем проекте не было настроенного хостинга, VPS, домена или доступа к deployment. Публичный адрес **не создан**; 127.0.0.1 — только BOX. Нужен предоставленный владельцем сервер/контейнерный хост с постоянным диском, доменом, HTTPS и правом запустить приложение. Платные сервисы, туннели и внешние аккаунты не создавались.

Подготовлены Dockerfile и compose.yaml (их сборка/развёртывание здесь не выполнялись). На целевом сервере: `.env` с реальным `SITE_ORIGIN=https://…`, `docker compose build`, `docker compose run --rm -it shop npm run setup:admin`, затем `docker compose up -d`. Именованный том `store-data` обязателен и не должен удаляться при обновлении. Контейнер работает непривилегированным пользователем. HTTPS reverse proxy должен передавать запросы на 127.0.0.1:8080 и ограничивать запросы примерно 9 МБ. Можно без Docker: Node 24, `npm ci --ignore-scripts`, `npm run build`, системный менеджер процессов для `npm start`, постоянный `DATA_DIR`, HTTPS proxy. Пример systemd не устанавливается автоматически.

## Проверка
- `npm test`: исходные 11 покупательских тестов.
- `npm run test:api`: 12 сценариев API + родительский тест, полностью временная БД; проверяются реальная PNG-загрузка, публикация, заказы, серверные цены, остаток/гонки, рестарт, доступ и ограничения.
- `node qc/managed-store-check.mjs`: Chromium, изолированный сервер/БД; пользовательский путь от загрузки фото в кабинете до заказа и прочтения/отмены в кабинете; 360/768/1024/1440.
- Старый `qc/holiday-world-check.mjs`: сохранённый демо-поток и motion-проверки.

CSV/Excel-массовый импорт не реализован и для первого товара не нужен. Рабочий путь — загрузка через кабинет. Реальная торговля ещё требует настройки администратора и размещения, а также подтверждённых бизнес-условий; платёжный шлюз не заявляется готовым.

Браузерные QC-скрипты требуют Playwright Core и Chrome (в BOX доступны); runtime магазина от них не зависит.
