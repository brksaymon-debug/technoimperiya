# Узкая оптимизация мобильного критического пути

Реальный LCP-элемент из Lighthouse: .holiday-environment. Сам фон был 107390 байт, но гораздо больший сетевой объём делили PNG Деда Мороза 822218 байт и логотипа 563255 байт. Переписывание приложения не предпринималось.

В мобильном браузере теперь выбираются: левый фрагмент исходного окружения 416×576 WebP 19184 байта (тот же исходный object-position:0% center, без перестановки сцены); PNG логотипа 535×184 181619 байт; Дед Мороз alpha WebP 416×675 76590 байт, с 692px вариантом для высокой плотности. Суммарно эти три запроса 277393 вместо1492863 байт: минус81.4%. Полные оригинальные PNG, альфа и настольное окружение/Дед Мороз не заменены; логотип остаётся настоящим PNG. Мобильный preload согласован с picture media, чтобы не скачивать оба окружения.

Один фактически выполненный Lighthouse mobile после responsive-исправления: Performance73 / Accessibility100 / BestPractices100 / SEO66; FCP1.952с, LCP8.703с, TBT59мс, CLS0.05847. Предыдущий LCP14.478с. Это улучшение, НЕ достижение целевых2.5с. После этого замера восстановлен исходный левый якорь композиции: финальный crop19184 вместо10518 байт замеренного правого варианта. Поэтому точное8.703с не выдаётся за повторное измерение финального crop. По ограничению один LH-перезапуск дополнительных прогонов не было.

Финальный мобильный smoke360/412, DPR1.75: браузер действительно выбирает новые ресурсы, все изображения загружены, overflow/errors/404 отсутствуют; включение каталога → tap добавления → корзина → количество2 работает. Обе production-сборки прошли. Скриншот screenshots/final-mobile.png обновлён после коррекции якоря.

Оставшийся предел: render-blocking исторический CSS~246KB и JS~494KB в несжатой локальной HTTP-раздаче, отсутствие заголовков кэша и симуляция мобильной сети. Это лабораторный результат, не полевой INP/FPS/GitHubCDN. Дальнейшие code-splitting/переработка CSS/настройка сжатия выходят за этот ограниченный проход и не имитировались скрытием сцены.
